# 经济性判据：bit、打包、指针、一行式

“省”只有三种收益：省 RAM、省代码尺寸、省指令周期。每一条都必须先问**省下来的是谁的资源、代价是谁的维护成本**。判据不满足时，可读性优先——这不是妥协，是内核维护的既有结论。

## 1. bit 优先：先看对象是谁

| 对象 | 结论 | 理由 |
|---|---|---|
| 硬件寄存器位域 | 用位操作 | 寄存器本身就是位的集合，`BIT(n)` / `GENMASK()` 是唯一可读写法 |
| 大量布尔集合（> 32 个独立标志） | 用 `bitmap` + `test_bit` / `set_bit` | 省的是数量级的内存与判断成本 |
| 少量稀疏布尔（< 8 个） | 独立字段或 `bool` | 省 3 字节不抵消多一层读改写的风险 |
| ABI / 协议 / flash 上的结构体 | **禁止 C 位域** | 布局依赖编译器与字节序，跨工具链必炸 |
| 并发共享的标志位 | **禁止位域** | 位域读改写不是原子操作，两个 CPU 各改一位会丢更新；用 `test_and_set_bit` + 明确锁 |
| 状态机 | 用 `enum` | 可读性收益远大于 4 字节 |

判定顺序：先问“这块内存是否跨越 ABI 边界”，再问“是否被并发写”，最后才问“能省多少字节”。前两问任一为是，bit 就不成立。

## 2. 位域的三条禁令

1. 不进 ABI：不出现在协议头、flash 布局、共享内存、驱动与固件交界。
2. 不进并发路径：除非整个字都在同一把锁里读写。
3. 不跨编译器：即使内部使用，也要 `static_assert` 校验总宽度，并在注释里写明假设。

允许的少数场合：纯内部、无并发、字段语义天然按位（如 3 个互斥状态）、且代码库已经在用同一种写法。

## 3. packed 三件套（缺一不可）

```c
struct __attribute__((packed)) fip_toc_entry {
    uint8_t  uuid[16];
    uint64_t offset;
    uint64_t size;
    uint32_t flags;
};
_Static_assert(sizeof(struct fip_toc_entry) == 36, "TOC entry layout");
_Static_assert(offsetof(struct fip_toc_entry, size) == 24, "TOC size offset");
```

- 断言布局，不只是总长度。
- 访问时 `memcpy` 到对齐的局部变量再用；**禁止对 packed 成员取地址**传给需要对齐的函数。
- 注释写清来源规范（哪个文档的哪张表）、字节序、保留位处理。
- 未对齐访问在某些 ARM 配置上直接 fault；x86 能跑不代表对。

## 4. 指针 vs 拷贝

| 情形 | 做法 |
|---|---|
| `sizeof > 16` 且只读 | `const struct foo *`，不拷贝 |
| 标量、指针、`<= 16` 字节的小 POD | 按值传，编译器会放进寄存器 |
| 需要修改调用方内存 | 出参指针，函数头注明 `out` |
| 用户态 / DMA / 跨地址空间 | 必须拷贝，且校验长度、检查 `copy_from_user` 返回值 |
| 需要在函数内长期持有 | 拷贝或明确所有权转移，禁止保存指向栈或临时对象的指针 |

硬规则：

- 每个指针参数在函数头注释里标 `borrow` / `transfer` / `out`，三者之一。
- 不为了少一次 `memcpy` 引入别名（两个指针指向同一对象）——除非函数头写明“允许重叠”并走 `memmove`。
- 小结构体 `memcpy` 通常被内联成几条指令，为它改成指针传递是负优化。
- 返回指向局部变量或已释放对象的指针，是 P0，不是风格问题。

## 5. 一行式的白名单与黑名单

允许压成一行：

```c
if (!dev || !dev->regs)
        return -EINVAL;

state = ready ? STATE_RUN : STATE_IDLE;
total += count * sizeof(*entry);
for (i = 0; i < n; i++)
        sum += buf[i];
```

禁止压缩：

- 错误处理与成功路径混在一行（`p = alloc(); if (!p) return;` 可以分行就别合并）
- 加锁、解锁、释放资源
- 带副作用的复合条件（`if (init() && start())`）
- 超过两个 `&&` / `||` 的复合条件——提取成命名布尔，或拆成分支
- 嵌套三元（`a ? b ? c : d : e`）

判定标准是**一个意图一行**，不是**一个分号一行**。审阅时把“压得太狠”的问题记为 P2，并在修复里给出拆分后的写法。

## 6. 复杂度上限（超出即 P2，除非有注释说明）

| 指标 | 上限 |
|---|---|
| 函数长度 | 60 行（不含注释与空行） |
| 嵌套深度 | 3 层（`if` / `for` / `switch` 合计） |
| 参数个数 | 6 个（超出考虑结构体入参） |
| 单行长度 | 80 列（目标文件另有约定则跟随） |
| 圈复杂度 | 15 |

## 7. 常见“省出来”的事故

| 写法 | 省了什么 | 付出了什么 |
|---|---|---|
| 位域存 6 个标志 | 5 字节 | 并发丢标志；跨编译器布局漂移 |
| `#pragma pack` 套协议结构 | 对齐填充 | unaligned fault；取址传参崩溃 |
| 为省拷贝传裸指针 | 一次 `memcpy` | 生命周期与别名 bug，难复现 |
| 把 `kmalloc` 换栈数组 | 一次分配 | 内核栈 16KB 上限，溢出即静默踩栈 |
| 删掉 `smp_wmb()` | 一条指令 | 在弱序 CPU 上偶发读到半初始化结构 |
| 用 `int` 存地址 | 4 字节 | 64 位平台截断，P0 |

## 8. 什么时候可以真的省

- 有实测数据（`size`、`objdump`、cycle 计数）说明收益；
- 收益落在真正的瓶颈（热路径、IRQ 处理、启动时间）；
- 省法的风险有对应测试或断言兜底；
- 注释写明“为什么必须这样”，避免后人“清理”掉。

四条不满足，就不要省。可审计性本身就是内核代码的核心指标。
