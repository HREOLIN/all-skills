# 审阅棱镜：分级、检测手法、最小修复

审阅的目标不是找得多，而是**排序正确**。一个 P0 漏掉，二十条 P3 也补不回来。

## 分级定义

| 级别 | 含义 | 典型后果 |
|---|---|---|
| **P0** | 阻断合入 | 内存破坏、越界、UAF、死锁、数据竞争、上下文误用、寄存器误写、未定义行为 |
| **P1** | 必须修，可本轮修 | 资源泄漏、返回值未检查、错误码丢失、栈溢出风险、ABI/布局错误、初始化顺序错误 |
| **P2** | 应修 | 边界条件、类型宽度、`const` 缺失、命名/单位不一致、缺失不变量注释、复杂度过高 |
| **P3** | 建议 | 格式、空行、拼写、include 顺序 |

判级只看**后果与触发可能性**，不看改动大小。一行改动可能是 P0，五十行重构可能只是 P2。

## 检测顺序

1. **读接口**：这个函数承诺了什么？返回值、所有权、上下文、错误码。
2. **读调用方**：谁传进来的？参数来自外部输入还是内部常量？
3. **读并发**：哪些数据被多个上下文访问？锁覆盖了哪些路径？
4. **读错误路径**：每个 `goto` / `return` 处，前面申请的东西都释放了吗？
5. **读边界**：0、1、最大值、最后一块、非对齐长度。
6. **读硬件**：每个寄存器写，对照手册确认保留位、W1C、顺序要求。

## P0 清单

### 内存与边界

- 外部输入的长度/偏移未校验就用于索引或 `memcpy`：追到来源，确认在**第一次使用前**校验。
- `size - hdr` 形式的下溢；`count * size` 的乘法溢出（用 `check_mul_overflow` 或显式除法校验）。
- 分配大小与后续写入大小不一致；flexible array 少算尾部。
- 栈上大对象（> 1KB）或 VLA；内核栈 16KB、中断栈更小，溢出无保护页。
- `copy_from_user` / `copy_to_user` 返回值被忽略，或未处理部分拷贝。

### 生命周期

- 错误路径与正常路径重复释放；`goto` 标签顺序错导致释放未申请的指针。
- 引用计数减到 0 后继续访问；`kfree` 后仍有指针可达。
- 保存指向栈变量、临时对象、或即将释放对象的指针。
- 设备移除/热插拔回调与工作队列、定时器的竞态。

### 并发

- 共享状态部分加锁（读加写不加，或只保护了赋值没保护复合操作）。
- 位域或 `u32` 标志的读改写在多 CPU 下丢更新。
- 在持有自旋锁时睡眠（`kmalloc(GFP_KERNEL)`、`mutex_lock`、`copy_to_user`）。
- 中断上下文调用可能睡眠的 API；中断与进程上下文用同一把锁但未关中断。
- 锁顺序不一致导致的 ABBA 死锁；持锁调用外部回调。
- 缺内存屏障（`smp_wmb` / `smp_rmb` / `dma_wmb`）的发布-订阅模式。
- RCU 读侧在 `rcu_read_unlock` 后继续使用指针。

### 硬件与 ABI

- 寄存器 read-modify-write 无保护，覆盖其他位；写保留位；W1C 位写成 0/1 语义搞反。
- MMIO 未用 `volatile`（或 `readl`/`writel`），编译器把连续访问合并/删除。
- 缺 `dsb` / `isb`：写完寄存器立刻读状态、开中断、跳转前未同步。
- packed 结构体未断言布局，或对其成员取址传给需要对齐的函数。
- 字节序：外设是小端，CPU 按本机序直接读；缺 `cpu_to_le32` / `le32_to_cpu`。

### 未定义行为

- 有符号整数溢出、负数移位、移位量 >= 位宽。
- 严格别名违规（用 `float *` 读 `u32` 缓冲区）；应使用 `memcpy` 或 union（GCC 扩展需注明）。
- 未初始化变量参与判断；结构体填充字节未清零就写 flash 或发给对端（信息泄漏）。
- `volatile` 被当作同步原语使用。

## P1 清单

- 每个错误分支都检查：申请的内存、时钟、regulator、GPIO、DMA 通道、`of_node` 引用是否释放/关闭。
- 返回值：flash 读、I2C/SPI 传输、`clk_prepare_enable`、`request_irq`、`platform_get_resource`。
- 错误码被后续调用覆盖，最终返回 0。
- 初始化顺序：先使用后初始化；`probe` 失败路径的顺序与成功路径不互逆。
- ABI：结构体字段顺序/宽度变更；`enum` 值变更；ioctl 号复用。
- 全局变量的并发初始化（`module_init` 与热插拔并存）。
- 递归（内核栈）与深调用链。

## P2 清单

- 0 长度、单元素、最后一块、非对齐长度的边界处理。
- `size_t` 与 `int` 混用、`size_t` 赋给 `u32` 的隐式截断、符号/无符号比较。
- `const` 正确性；不该导出的符号没加 `static`。
- 命名不一致、缺单位后缀、布尔命名不是 `is_`/`has_`。
- 缺关键注释：锁前提、可睡眠性、单位、硬件勘误、不变量。
- 复杂度超标（见 `economy.md` 的上限表）。
- 可测试性：错误路径无法注入。

## 检测手法（比清单更重要的部分）

| 问题 | 怎么找 |
|---|---|
| 越界 | 对每个 `size`/`count` 顺着调用链往上追到源头；问“如果它是 0 / 0xFFFFFFFF / 不整除会怎样” |
| UAF | 搜索对象的每一次 `free`/`put`，检查之后是否还有解引用路径 |
| 泄漏 | 把函数体按 `goto` 标签切开，逐段对账“已申请 vs 已释放” |
| 竞争 | 列出每个共享变量的所有写入点，逐一问“这里持锁了吗？谁可能同时写？” |
| 上下文误用 | 对每个可能睡眠的 API，向上追到中断入口 |
| 寄存器错误 | 对照手册的位定义表，逐位确认保留位、W1C、读清语义 |
| 屏障缺失 | 找“写标志 → 写数据”或“写数据 → 写门铃”的模式，确认两侧都有屏障 |

## 最小修复原则

- 只改触发缺陷的行及其直接依赖。
- 保持目标文件的风格与既有错误处理惯例。
- 修复要能独立成立：不依赖“顺便把另一个 bug 也修了”。
- 给出修复后必须成立的断言或测试点（哪怕只是注释说明如何验证）。
- 无法给出安全修复时，明确说“需要更多信息”，并列出需要哪几项（手册页、调用链、寄存器值、复现步骤）。

## 不要做的事

- 不把风格问题混进 P0/P1 的列表里稀释注意力。
- 不在没有触发条件时写“可能存在竞态”。
- 不为了展示深度而提出与平台无关的通用建议（“建议加日志”“建议写单元测试”）。
- 不假设未展示的代码是正确的；但也不假设它是错的——标“待确认”。
