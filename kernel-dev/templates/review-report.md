# 审阅报告骨架

复制并填充。没有内容的级别整行删掉，不要留空标题。

```markdown
结论：<可合入 | 需修改 | 需重写>（P0×N，P1×N，P2×N，P3×N）

## P0

1. `<file>:<line>` — <一句话后果>
   - 触发：<什么输入/时序/配置会让它发生>
   - 修复：
     ```diff
     - <旧代码>
     + <新代码>
     ```

## P1

2. `<file>:<line>` — <后果与触发条件>
   - 修复：<最小改动，可只给代码片段>

## P2 / P3（合并）

- 命名：<位置>，`xxx` 应为 `yyy`（同文件内已有 `yyy` 写法）
- 注释：<位置> 缺锁前提说明
- 格式：<位置> 缩进与文件其余部分不一致
（最多列 5 条，其余以“同类还有 N 处”概括）

## 自检

- 并发：<已覆盖哪些路径 / 未覆盖哪些>
- 错误路径：<逐条对账结果>
- 整数：<size/count 的来源与校验点>
- 对齐/打包：<涉及的结构体与断言>
- 资源：<get/put、申请/释放配对结果>

## 待确认

- <需要的信息：手册页、调用链、寄存器值、复现步骤>
```

## 一份填好的示例

```markdown
结论：需修改（P0×2，P1×1，P2×3）

## P0

1. `fip.c:142` — TOC 中的 size 未校验，可越界读 flash 后任意长度
   - 触发：TOC 损坏或被篡改，size 字段为 0xFFFFFFFF
   - 修复：
     ```diff
     -	memcpy(dst, (void *)(base + entry->offset), entry->size);
     +	if (entry->size > FIP_MAX_PAYLOAD)
     +		return -EINVAL;
     +	memcpy(dst, (void *)(base + entry->offset), entry->size);
     ```

2. `bl2.c:88` — 在中断上下文调用 `kmalloc(GFP_KERNEL)`
   - 触发：任意一次定时器中断命中该路径
   - 修复：预分配缓冲区，中断里只做 `memcpy` 与入队

## P1

3. `bl2.c:120` — `probe` 失败路径未 `clk_disable_unprepare`
   - 修复：为每个已 `prepare` 的时钟补 `err_*` 回退标签

## P2 / P3（合并）

- 命名：`bl2.c:31` 的 `t` 应为 `timeout_ms`，且缺单位
- 注释：`fip.c:60` 缺“调用者必须持有 `fip_lock`”说明
- 格式：`fip.c` 出现 4 空格缩进，与同文件其余 tab 缩进不一致

## 自检

- 并发：已核对 3 处共享状态的加锁路径，`state` 的写点在 `irqsave` 内
- 错误路径：`fip_load` 与 `fip_check` 的全部 6 个返回点均已对账
- 整数：`offset`、`size` 均来自 TOC，已在入口校验上界
- 对齐/打包：`fip_toc_entry` 已断言 36 字节，访问一律 `memcpy`
- 资源：`clk` 配对 3/4，第 3 条即缺口

## 待确认

- BL2 阶段是否开启 D-cache？影响第 2 条的 DMA 缓冲区处理
- 需要 `fip.c:142` 上游的 TOC 生成代码，确认 size 是否可能为 64 位
```

## 篇幅控制

- P0 每条不超过 8 行；超过说明你在讲原理，不是在报问题。
- 一次审阅的正文控制在 80 行内；细节放“待确认”或另起文件。
- 用户只要结论时，只给“结论 + P0 清单 + 自检面板”，其余省略。
